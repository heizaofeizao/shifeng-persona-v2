## 一、已修 · 元数据式自陈（用户反馈）

**用户原话**：「我没有专门谈过」「没系统性想过」这类也是 AI 模拟人类时的语言，而不是真实语言。

**定性**：这是**元数据式自陈**——向读者汇报自己的发言记录 / 知识状态。与 v2.4 的元叙事开场（#11）同族，都是**元层面自我描述**：
- #11 描述"我接下来要怎么发言"
- #12 描述"我的发言记录 / 知识状态"

**一句话判据**：台词里出现「我谈过 / 我没谈过 / 我写过 / 我研究过」这类**行为史陈述** → 即元数据自陈。允许的是「我懂 / 我不懂 / 我说不好 / 我没想明白」这类**当下状态表达**。

**核心架构变更**：诚实机制从「台词内声明」迁移为「**交付注**」——

| | 旧（≤v2.4） | 新（v2.5） |
|---|---|---|
| 台词 | 「直播带货我没专门写过。不过……」 | 「要说 LLM 是新的工业革命，那直播带货就是上一次"新的工业革命"——"新"字用得属实随意。」 |
| 诚实性 | 靠台词自陈 | 靠**语气**（软、短）+ **交付注**（回答之外另起一段元信息） |
| 原理 | 角色在汇报档案 | 台词 = 石枫说的话；交付注 = 给读者的元信息，两者分离 |

**落点（7 个文件）**：

`_bm25_index.pkl` 是**派生缓存**，不是源码；落在包内会让每份安装白占 11 MB。

**修复方式**：缓存移出包体，落到包外用户缓存目录（不再靠"打包时记得排除"这种人工纪律）。

| 落点 | 变更 |

| `scripts/retrieve.py` | 新增 `cache_dir()` / `index_path()`：缓存默认 `~/.workbuddy/cache/shifeng-persona-v2/`，文件名按**语料绝对路径 sha1**命名（多语料互不覆盖）；层级 `SHIFENG_CACHE` 环境变量 > 用户缓存目录 > 系统临时目录 |
| 同上 | 新增 `--cache-info`（看缓存位置/体积/是否在包外/包内有无遗留）与 `--clean-cache`（清缓存，含旧版包内遗留）；`--stats` 增印缓存路径与"在包外"判定 |
| 同上 | 常量 `LEGACY_INDEX` 仅用于**侦测**旧包内缓存，不再读写；模块 docstring 补缓存说明 |
| `scripts/run_regression.py` | 旧断言"索引缓存已生成"改为 **2 条打包守卫**：① 缓存在包外 ② 包内不得存在任何 `.pkl`（os.walk 扫描）；断言总数 46 → **47** |
| `v2/.gitignore` | 新增：`*.pkl` / `_bm25_index.pkl` / `__pycache__/` 等，作版本控制与打包双重闸门 |
| `modules/retrieval-guide.md` | 使用规范补缓存位置、`--cache-info` / `--clean-cache` / `SHIFENG_CACHE` 说明 |

## 六、一处工具行为教训（非 skill 缺陷）

本轮修改中多次出现**同一文件的多个编辑只有部分生效**：同一批次对同一文件下多个编辑时，后写覆盖了前写的中间态。受影响的改动（`_int()` 定义、`import unicodedata`、tokenize 去重、SKILL.md 三处、qc.md 失败树、style-short 两处）已逐一补回并复验。

**规程**：今后对**同一文件**的多处修改一律**串行**下发，每改一处确认后再改下一处；跨文件可并行。已同步写入长期记忆。
